# 审校提示词模板（多路并行，客户版必过）

> 用法：把纪要按章切成 6–8 份，每份一个子代理，粘同一段模板，只改「要核的章节」和「页码」。
> 关键：每路都要能读到**全部素材稿**（不是只读那一章），否则它没法判断"这句到底有没有依据"。

---

## 一、主模板

```
你是审校员，只做核对，不改文件。

**任务**：核对客户可见会议纪要的「{{章节名}}」，逐句判断这句话在来源里能不能找到依据。

**纪要原文**：
cd {{工作区}}
python3 -c "
import fitz;d=fitz.open('{{纪要PDF路径}}')
print(d[{{页码}}].get_text())"

**依据来源（按优先级）**：
1. {{素材稿路径}} —— 主依据，每条形如 `- 〔L123〕客户：…`，L 号指向转录原文行
2. {{转录原文路径}} —— 用来验 L 号是否真有那句话
3. {{经理录音路径}} —— **经理内部指示，不算现场，必须单独标"经理"**

**判定标准（严格）**：
- 现场 = 素材稿里找得到，意思没加强（改写可以，但原文"可能/大概"不能写成"就是"）
- 经理 = 只在经理录音里，现场没说过
- 产品 = 界面事实（截图里看得见），客户没点头前算我方承诺
- 无据 = 都找不到，属行文推论或常识

**输出格式**：

| # | 纪要原句（截断45字） | 判定 | 依据（〔L号〕+原句截断40字）| 问题与改法 |
|---|---|---|---|---|

最后一行统计：`共 N 句｜现场 a｜经理 b｜产品 c｜无据 d`

**宁可判严，不要放水。拿不准写"无据（拿不准）"。**
```

---

## 二、按章追加的"特别盯什么"

切章之后，每路加一句针对这一章的高危项，命中率会明显高：

| 章节 | 追加这句 |
|---|---|
| 本次沟通的目的 | 有没有"行文归纳"被当成客户确认的目的 |
| 贵司现状 | 数量、比例、岗位、系统名；有没有把客户的**提问**写成客户的**处境** |
| 客户提出的问题 | 这章最危险：客户问"能不能做"≠客户有这个痛点；有没有我方替客户诉苦 |
| 方案各场景 | "自动/直接/不会/不用"逐个回原文；范围外延（某个环节被扩成"所有业务"） |
| 模块表 | 有没有产品功能被写成客户认可；有没有内部表述（按内部要求/待确认） |
| 用户与费用 | 用户数、账套数、折扣、首年/次年费用；数字必须逐字回原文 |
| 上线路径与时间 | 原话里的"但是/前提是"有没有被删；日期有没有被弱化（12 月 25 日→12 月下旬） |
| 下一步 | 每一行都要有原话；有没有把内部动作写成对客户的义务 |

## 三、改稿阶段（不进子代理，由主代理做）

审校结果回来后**整章重写，不做逐条打补丁**——28 处零散修改会互相顶，重写一遍更快也更一致。

改完必跑四项机器门禁（`check_material.py` + 手工 grep）：

```bash
# 数字、实体、承诺句、全称断言
grep -nE "都|所有|一律|全部|任何|每张" 纪要.html
grep -nE "自动|保证|不会|不用|直接" 纪要.html
```

再扫一遍内部词汇：`经理 / 待确认 / 待定 / 存疑 / 〔L / 素材稿 / 录音 / 内部`。

---

## 四、别做的三件事

1. **别让子代理改稿**——它一改，你就不知道它改了什么。只让它出判定表。
2. **别只读那一章**——只给一章正文、不给素材稿，它会把"听起来合理"判成"有据"。
3. **别把"审校通过"当签字**——审校也会漏，最终仍需人看一遍对照表。
